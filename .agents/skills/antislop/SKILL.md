# Anti-Slop: Rules for AI Coding Agents

> **Objective:** Any UI, code, or copy should feel **crafted by an expert human designer & engineer**, never generated by an automated AI template.

---

## 1. Core Principles & Purpose Test

Every visual or architectural decision must pass the **Purpose Test**:
1. **No Defaults:** If an element exists only because "it's the AI default" (e.g. purple gradient, centered robot icon, generic card grid), it fails.
2. **One Deliberate Accent:** An accent color guides the eye to the key action. If it is splashed on every border, badge, and icon, it loses meaning.
3. **Evidence Over Claims:** Never show fabricated statistics (`+24% this month`), fake reviews, or dummy counters unless backed by real database data or clearly marked as a placeholder.
4. **Hierarchy Over Decoration:** Shadows, borders, and glassmorphism exist to establish z-index elevation and separation—never as decorative wallpaper.

---

## 2. UI & Visual Anti-Slop Rules

### Colors & Gradients (R-01, R-29)
- **Forbidden:** Generic blue-to-purple, purple-to-pink gradients as default cards/backgrounds.
- **Rule:** Palette must be derived from the product's authentic brand identity (e.g., Meta WhatsApp green `#10b981`, slate `#0f172a`, and clean neutral surfaces).
- **Rule:** Gradients are reserved for intentional visual emphasis (primary action button, brand emblem), not pasted across every card.

### Surface Elevation & Glassmorphism (R-10, R-12)
- **Forbidden:** Glassmorphism (`backdrop-filter: blur`) on every container simultaneously.
- **Rule:** Dose cap of at most 1–2 elements (the floating action bar or a modal overlay). All other surfaces remain crisp, solid matte layers.
- **Rule:** Avoid ultra-diffuse shadows that make pages feel floaty and ungrounded. Use crisp, shallow 1px–3px shadows with high-definition border strokes (`1px solid rgba(15, 23, 42, 0.08)`).

### Badges, Capsules & Radii (R-09, R-11)
- **Forbidden:** Every element styled as a pill (`border-radius: 9999px`)—buttons, inputs, cards, and tags.
- **Forbidden:** Decorative capsule badges above headers repeating what the title already states.
- **Rule:** Establish an intentional radius scale:
  - Cards & Panels: `12px` to `16px`.
  - Buttons & Inputs: `8px` to `10px`.
  - Status Indicators & Pills: `9999px` strictly for status chips (e.g., `Online`, `En Cotización`).

### Status Indicators & Motion (R-13, R-19)
- **Forbidden:** Endless pulsing glows on static or purely decorative elements.
- **Rule:** A pulsing dot or badge must indicate a **real, active real-time connection** (e.g., active WebSocket, live Meta Webhook HMAC verified, incoming voice call).

### Layout & Composition (R-05, R-14)
- **Forbidden:** Cookie-cutter layouts (e.g., 6 identical stat boxes + 1 empty chart).
- **Rule:** App screens must be built around the real workflow and decisions the user makes on that view:
  - In a Conversational CRM: fast triage of inbound WhatsApp messages, deal progression in the Kanban funnel, 24h Meta window countdown, and quick customer assignment.

---

## 3. Code & Copywriting Anti-Slop (R-16, R-code)

- **Forbidden AI Buzzwords:** "Seamless", "Revolutionary", "Cutting-edge", "Supercharge", "Game-changer", "Next-gen".
- **Rule:** Speak in concrete, operational terms: "Official Meta WhatsApp Cloud API v22.0", "Webhook HMAC-SHA256", "Tiempo de respuesta < 750ms".
- **Forbidden Comments:** Stating the obvious (`// Increment i by 1`, `// Render the component`).
- **Rule:** Keep comments focused on business logic, security constraints, and protocol requirements (e.g., Meta 24-hour messaging policy, idempotency deduplication).

---

## 4. Delivery Gate Checklist

Before delivering code or UI, run this gate:
- [ ] **No Default AI Palette:** Is the color scheme tailored to the specific product and brand?
- [ ] **No Pill/Capsule Spam:** Are shapes and radii structurally varied rather than all pills?
- [ ] **No Fabricated Metrics:** Are all numbers, badges, and counters derived from real data or explicit database queries?
- [ ] **No Wallpaper Glass/Glow:** Are blur and glow strictly capped to key interactive elements?
- [ ] **Functional Completeness:** Does every button, filter, and tab connect to a real handler, modal, or action?
- [ ] **Accessibility & Contrast:** Do all text labels meet WCAG AA contrast ($\ge 4.5:1$)?
- [ ] **Real Utility:** Does the screen solve the operator's job without filler or empty voids?
